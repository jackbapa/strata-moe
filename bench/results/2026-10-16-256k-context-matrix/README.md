# 256K 上限、不同输入长度的 A3B 测试

测试机为 Windows、AMD Ryzen Threadripper 3960X（24 核/48 线程）、128 GiB RAM，三张驱动报告 22,528 MiB 的 RTX 2080 Ti。主模型均为相同的 Unsloth Qwen3.6-35B-A3B UD-IQ3_S GGUF（SHA-256 `66a3ca888ce13482b40c333db2432c0ebde3a7b13754fc29f0c6f5e89703ec66`）。全 GPU 路径还加载匹配的 Q8_0 MTP 草稿，K2；6 GiB、历史 2 GiB 与纯 CPU 路径不使用 MTP。

这轮直接使用引擎的驻留 `GEN` token 协议。每一行启动一个新进程，等 `READY` 后才开始计时，发送未缓存请求；启动时间另记在 JSON 中。所有发布档位的**配置上下文上限**都是 262,144 token，实际物理 KV 缓存按请求长度分档，不能把 256K 上限理解成每行都输入了 256K。可比矩阵的四个输入长度为 7、1,024、8,192、32,768 token，均要求 128 个输出 token、贪心采样。输入 token ID 来自对 `Explain mixture of experts briefly.` 的一次 GGUF tokenizer 编码，并重复、裁剪到精确长度；因此这是**合成、重复输入的吞吐测试**，不是自然文章阅读或模型质量测试。重复结构会改变 MTP 接受率和输出速度，不能拿它和先前另一种合成输入的 50K/256 请求作引擎提速对比。

首 token 时间从写入 `GEN` 到第一个 `T <id>` 计，不是 HTTP 响应首字节。预填充和输出速度分别根据引擎的 `DONE` 内部 `prompt_ms`、`decode_ms` 与实际 token 数计算。GPU 数字是 `nvidia-smi` 对**整卡**使用量的 200 ms 采样峰值；RSS 是引擎进程采样峰值。短暂峰值可能漏采。每个长度目前是一轮完整请求，**没有重复测试的中位数**。

全 GPU：GPU 0 全驻留、Strata 分组 IQ 专家核、MTP K2，F16 短档/Q8 长档 KV；命令和环境见 [`full.json`](full.json)。6 GiB：GPU 1、`--vram-mib 6144` 引擎规划预算、2,048 MiB 专家显存缓存上限，GPU 主干和部分专家驻留显存，未命中专家从系统内存由 CPU 计算；默认 24 个 CPU 线程。≤64K 物理 KV 档用 GPU，更大档用系统内存。整卡采样值包含其他驱动占用，**不是物理 6 GiB 显卡验证**。纯 CPU：16 线程，模型运算不用 GPU。两种低资源模式的批大小和线程数不同，因此这是各自发布配置的表现，不是仅改变 GPU 使用与否的单变量 A/B。所有参数和逐轮结果分别在 [`6g.json`](6g.json)、[`cpu.json`](cpu.json)；原始引擎日志为同目录的 `<mode>-<input>-01.log`。

6 GiB／32K 的引擎日志显示约 2,026.5 MiB 专家显存缓存；输出阶段有 111,762 次 GPU 专家行命中和 10,158 次 CPU 专家行计算。预填充阶段的上传量达 556,803.7 MiB，说明低显存档的长输入仍有大量专家搬运开销。历史 2 GiB／8K 与当前 6 GiB／8K 的首 token 分别是 159.261 和 44.482 秒，输出分别为 7.01 和 27.29 token/s；两档同时改变了显存预算、缓存、批大小和 KV 位置，不能把差值归因于单一因素。

在仓库根目录、模型和 CUDA/CPU 引擎均已安装后复现：

```powershell
.\.venv\Scripts\python.exe bench\a3b_256k_matrix.py --mode full --lengths 7 1024 8192 32768 --output 128
.\.venv\Scripts\python.exe bench\a3b_256k_matrix.py --mode 6g --lengths 7 1024 8192 32768 --output 128
.\.venv\Scripts\python.exe bench\a3b_256k_matrix.py --mode cpu --lengths 7 1024 8192 32768 --output 128
```

三种模式应依次单独运行，避免共用 CPU 核心使比较失真；跑全 GPU 档前也须停止 GPU 0 上已有的模型服务，测后再启动。脚本按 `<mode>.json` 中已完成的 `(input_tokens, trial)` 跳过，失败的长度可单独重试。转向 6 GiB 测试前完成的 2 GiB 预算 7、1K、8K 输入数据保留在 [`2g.json`](2g.json)，其中 8K 行首 token 159.261 秒、预填充 51.47 token/s、输出 7.01 token/s；2 GiB/50K 被停止，**没有**完整速度结果。全 GPU 50K/128 的单次合成重复输入仍保留在 [`full.json`](full.json)，不与四档矩阵混算。此前的 [另一种合成输入的 50K/256、三轮 API A/B 报告](../2026-10-16-a3b-iq3s-combined-exact-r3/README.md) 和 [1K 上限、7 输入的低资源三轮报告](../2026-10-16-release-low-resource/README.md) 是不同条件的历史实验，不应与本矩阵合并计算峰值或中位数。
