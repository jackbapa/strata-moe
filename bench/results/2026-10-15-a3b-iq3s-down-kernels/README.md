# A3B IQ3_S grouped down-kernel experiment, 15 October 2026

This experiment changed only `G:\Strata-Moe`. The original `G:\Strata` project was read-only. The tested target was the single Qwen3.6-35B-A3B UD-IQ3_S GGUF, whose mixed quantization includes IQ2_S gate/up, IQ3_S or IQ4_XS down, and Q6_K dense tensors. The Q6_K tensors are part of this same model, not another model. GPU 0 was an RTX 2080 Ti (sm_75, 22,528 MiB). The 8096 service used a 262,144-token context, F16 short KV tier, Q8_0 MTP K=2, exactly 50,000 uncached prompt tokens and 256 generated tokens. The 8096 original service was restored after the runs and `/v1/models` returned the loaded model.

`STRATA_A3B_DOWN_MODE` is opt-in and defaults to 0. Mode 1 uses a new 16-lane sub-warp for A3B's 512-input IQ3_S down projection. Each row has 16 quantized dot parts, so two independent rows fill a warp; it uses Strata's existing `Split<21>` decoder, grouped expert routing, and the same floating-point reduction tree as the default grouped path. Mode 2 adapts the original Strata shared-activation down kernel to A3B's separate down-tensor pointer. Both modes require split IQ2_S/IQ3_S 2048/512 tensors; IQ4_XS down layers remain on the default path. No CPU expert computation or new model quantization is involved.

The CUDA build completed with `build-targets.cmd`; raw compiler output is `build.log`. The real-weight parity harness compared packed original grouped output with separate-tensor output for **all 40 layers**, varying one through four entries per expert group. Modes 0, 1 and 2 each had **zero differing floats** with `STRATA_A3B_FUSED_GU=0`; mode 1 also had zero differences with fused gate/up enabled. The full logs are `parity-gu0-mode{0,1,2}.log` and `micro-gu1-mode1.log`. The microbenchmark alternated packed and split calls within each process (three pairs of 200 CUDA-event-timed calls); raw results for modes 0, 1 and 2 are `micro-gu0-mode{0,1,2}.log`. Mode 1 was the most promising IQ3_S candidate; mode 2 was slower for a one-entry group, so only mode 1 went to the API comparison. Microbenchmarks are diagnostic; their packed/split times include different pointer layouts and are not whole-model throughput.

The API comparison used **the same rebuilt executable** (`sha256 94844422f50dec87417b15d09e8263e260815a7dafe0f5defec63734f98a5191`), target GGUF (`66a3ca888ce13482b40c333db2432c0ebde3a7b13754fc29f0c6f5e89703ec66`), MTP GGUF (`f6cb995fab78e7284097b2e13508e8daad4ffc6a747b433aef399f4e48524b5a`), exact request and sampling. The original selected config was the baseline; `variant-config.json` differs by `STRATA_A3B_DOWN_MODE=1` and its engine-log path. Each service was loaded fresh, and requests ran in baseline, sub16, baseline, sub16, baseline, sub16 order. The suite's `arms/*/runNNN.json`, event/resource logs, and `comparison.json` retain exact raw measurements and identities.

The output runs were 81.3, 81.5, 80.9 tok/s for baseline and 84.6, 83.1, 81.9 tok/s for sub16. Thus the median output difference was **+1.8 tok/s (+2.2%)**, while first-model-token latency increased by 0.238 s and prefill fell by 12.6 tok/s. All six 256-token answers had the same SHA-256 `03fc938322f153aa7f2b93b062ffc6b820b034322ac86a5b8fceb7d7758a1bf7`; each run offered 238 and accepted 136 MTP tokens. The observed VRAM peak was unchanged. This is a small, isolated decode gain, not the 100 tok/s target; the selected default remains mode 0. The `output-node-explicit.sqlite` partial profiler trace showed IQ3_S down kernels occupying only about 270 ms of a 2.602 s captured GPU span, so a down-only optimization has a limited end-to-end ceiling.

After measuring, the mode-2 template was narrowed so the original packed Strata LDS call retains its packed-pointer specialization while mode 2 uses a split-pointer specialization. Mode 2's final template edit has not been rebuilt or retested; the reported measurements are from the earlier compiled form. Mode 1 and the selected default do not depend on that edit. Rebuild and repeat mode-2 parity before considering mode 2 for use.
