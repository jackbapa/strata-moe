# 16 GiB 引擎预算下的混合专家 + MTP 初步记录

这是在后续测试停止前已完成的有限测量；**没有**完成物理 16 GiB 显卡、真正填满 256K、不同上下文上限或大规模重复测试。测试机为 Windows、Ryzen Threadripper 3960X、128 GiB RAM、驱动报告 22,528 MiB 的 RTX 2080 Ti GPU 0。主模型是 Unsloth Qwen3.6-35B-A3B UD-IQ3_S，MTP 是匹配的 ggml-org Q8_0，K2。`--vram-mib 16384` 限制的是引擎的显存规划预算；下表的显存峰值为 `nvidia-smi` 对**整卡**的采样，包含约 90 MiB 起始占用和驱动开销。

两组均设置 `--ctx 262144 --batch 2048 --hybrid-experts --cpu-expert-pool --pcie-frac 0.25 --kv-tiered --kv-tiered-f16-short`，16 CPU 线程，GPU 0；唯一的主要配置差异是是否加载 MTP 草稿及其验证参数。输入来自 `docs/DETAILS.md` 的 UTF-8 文本，经 GGUF tokenizer 编码后重复并裁剪到表中长度，**不是三份独立自然文本**。每次启动新引擎，等 `READY` 后发未缓存 `GEN` 请求，要求 128 个输出 token。请求到首个模型 token 的时间不含模型加载，也不是 HTTP 首字节；预填充和输出速度来自引擎内部计时。所有输入加输出均不超过 64K；日志确认物理 KV 是 **65,536 cells、F16 K/V**，尽管配置上限为 256K。

| 配置 | 上下文上限 | 实际输入 | 轮次 | 首个模型 token (s) | 预填充 (token/s) | 输出 (token/s) | 整卡显存峰值 (MiB) | 引擎 RSS 峰值 (MiB) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 混合 + MTP K2 | 262,144 | 1,024 | 2 | 4.143 | 247.49 | 63.50 | 16,483 | 12,943.8 |
| 混合，无 MTP | 262,144 | 1,024 | 2 | 3.893 | 263.24 | 44.77 | 15,725 | 12,183.8 |
| 混合 + MTP K2 | 262,144 | 8,192 | 1 | 18.56 | 441.49 | 51.47 | 16,859 | 13,213.3 |
| 混合，无 MTP | 262,144 | 8,192 | 1 | 17.79 | 460.79 | 45.08 | 16,097 | 12,443.7 |
| 混合 + MTP K2 | 262,144 | 32,768 | 1 | 71.16 | 460.53 | 46.99 | 16,869 | 13,217.6 |

1K 的第二轮两组输出 token 哈希一致；8K 的输出哈希不同，因此不能宣称 MTP 与无 MTP 的输出逐 token 一致。两组的草稿驻留、专家缓存容量和计算路线也不同，不能把表中差值全归因于 MTP 算法。32K 没有无 MTP 对照。日志记录 16 GiB MTP 档的专家缓存约 9,960 MiB，1K 请求确实调用了 CPU 专家池（111 行），所以这是实际混合路径；该档解码并非全部在 GPU 执行。原始数据和精确参数在 [`16g-hybrid-mtp.json`](16g-hybrid-mtp.json) 与 [`16g-hybrid-no-mtp.json`](16g-hybrid-no-mtp.json)。单独的[早期 1K 短句重复输入试跑](../2026-10-16-16g-hybrid-mtp/16g-hybrid-mtp.json)使用另一种内容，不并入此表。

引擎显存规划预算不等于物理卡容量，也不等于全模型驻留。此轮对 **64K 物理 KV 档**的显存与速度有观察，但没有对 128K／256K 物理档作测量。低于 16 GiB 的混合 + MTP 门槛同样没有通过这份记录验证。
